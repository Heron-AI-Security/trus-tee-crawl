# Pitfalls, corrections and decisions

A practical guide for anyone repeating this work. It records what went wrong, how each problem was
resolved, which instructions turned out to be wrong, and why the key decisions were taken.

## 1. Operating rules that would have prevented most problems

1. **Check where you are before every command.** Run `hostname`. Four places are in play: laptop
   (PowerShell), Cloud Shell, the master `tdx-lab`, and the worker `tdx-lab-worker`.
2. **All SSH logins start from Cloud Shell.** A VM cannot SSH to another VM with `gcloud compute ssh`
   (it fails with "insufficient authentication scopes"). Leave with `exit`, then log in again.
3. **Paste one command at a time after any `ssh` or `tmux new`.** Lines typed while a login or session
   is starting are swallowed.
4. **Run long jobs inside tmux, and log to a file.** Detach with **Ctrl+B, release, then D**.
   Re-attach with `tmux attach -t <name>`.
5. **Do not rely on `| tail -N` for visibility.** It prints nothing until the command ends. Use
   `| tee file.log | tail -N`.
6. **Never compare hashes by eye, and never retype evidence.** Let the shell compare
   (`[ "$a" = "$b" ] && echo SAME`). Retyped hashes in this work were the wrong length.
7. **Compare hashes, not file sizes.** A wrongly formatted seed file had the right size by coincidence.
8. **Clear the screen (`clear`) before a long paste**, and write results to a file you then `cat`.
9. **Add Git files by name**, never `git add .` or `git commit -a`, and read `git log --stat` before pushing.
10. **Never run `hdfs namenode -format` twice.** It erases HDFS.
11. **Do not touch folders you did not create** (for example unknown `entry…` folders under
    `/sys/kernel/config/tsm/report/`).
12. **Label every time with its source and zone.** VM clocks are UTC; tools on the laptop print local time
    (India Standard Time, UTC+5:30). Convert before writing "UTC".
13. **Keep test artefacts in a named folder**, not `/tmp`, which is cleared when a VM restarts.

14. **Read a real sample before writing a check that depends on another tool's output.** Run one read-only command, look at what it prints, then write the check. (The first tamper demo looked for an error text that the client never prints, and assumed `hdfs dfs -ls` prints absolute paths.)
15. **Do not test a check only against stand-ins you wrote from the same assumption.** Such a test cannot find the assumption. Prefer evidence that our own code writes (audit lines, records), and run the check on real logs.
16. **Move files in one pack, with a printed fingerprint, and verify it on arrival.** Look at the unpacked folder (`pwd`, `ls`) before running anything from it. Several browser downloads in a row lost files; a small web server in Cloud Shell (`python3 -m http.server 8080`, opened through Web Preview) worked.
17. **Commit gate and documents.** Before any commit, check that the files are identical (by fingerprint) to the files that ran, in the cluster folders, on the laptop and in a fresh clone; abort on any difference. Write the documents after the code ran, from a fresh copy of the branch, and check their numbers against the evidence (`docs_facts_check.py`).
18. **Rehearse code with the real libraries before sending it.** If the real libraries cannot be had, say in the message exactly what could not be rehearsed. Code checked only against stand-ins written from one's own assumptions fails where the assumptions are wrong (the contract tests, 7 October).
19. **Documents and programs go in separate commits**, programs first and each gated; a tool's data file counts as a program.
20. **Test a check against a known fault before trusting its pass.** The contract comparison was run once with the old job, which has known defects, and had to report them.
21. **Do not rename or add steps.** Steps keep the names already committed; anything new from the mentor goes inside an existing step as a baby step (4.5.2, 4.6.1 to 4.6.3, 5.3.3).
22. **Do not draft messages to teammates or mentors unless asked.**
23. **A stand-in must model the real tool's constraints.** A stand-in written from the same assumption as the script cannot find that assumption's error: the admin tool refused the wrapper and the stand-in did not.
24. **After moving a file, find out where the running writer writes.** A rotation does not stop a process that holds the file open; before saying something was not logged, look in the archive too.
25. **Tools that inspect the cluster ask for the plain client themselves.** They must not depend on the cluster's current mode or on the guard they inspect.
26. **Collect task logs right after a run.** They expire (after 3 hours here, with log aggregation off).
27. **Say what a number or a label means, from the source.** `allowed=false` on a delete is not "denied"; "about 40 jobs" had no source; a count that includes its own list is not "files listed".
28. **Never cut a search that a claim rests on.** A `head` hid the lines that made a statement about Nutch false; if the output is cut, say so and do not conclude from it.
29. **A guard must test the thing it guards.** The failure test checked that the client program was alive, not that the job was running.
30. **A setting that governs two different questions should be split when one of them is harmless.** Reading a file's content and asking for its status are different; refusing the second broke a real file system test.
31. **Read a script's start-up checks before giving the command that starts it**, and run a script that is not executable in the repository with `bash`.
32. **Attach a file in the same message that creates it, and check that the card is there.** A file that is written but not presented cannot be downloaded.
33. **Test code that removes secrets with the target's own shell tools and with planted fake secrets.** One `awk` option worked on one variant and not on the one Ubuntu uses.
34. **Check the class hierarchy before drawing a conclusion from a listing.** A listing against the wrong parent class said nothing.
35. **Measure the speed before planning a long transfer.** Five copies of 135 MB at 130 KB/s would have taken over an hour.
36. **Before any commit of code or documents, look at the actual repository, not at memory.** Fetch the branch and run `ops/attested/preflight.sh`: it refuses unless the working copy is at the latest commit on GitHub, every place that states a status says what `docs-status-expected.tsv` requires, no earlier facts list has changed its result since its baseline, and every file of `docs/` passes the audit (`docs_audit.py`: links and anchors, contents lists, the docs index, table shapes, numbering). A package is built only after it passes, and the verification after the commit runs it again. A status, a head, a count or a file name that is written from memory is a defect.
37. **Before a documents commit, read every file of `docs/`, not only the files that the change touches.** The preflight prints a report of every file (its last commit, the newest date it mentions, how many lines speak of open or pending work); read the status-bearing text of each file against the repository and the evidence, and add what you find to `docs-status-expected.tsv`. A status is stated in many places (the plan, the report, the index, the state page, the handoff, the run comparison, the limitations log), and a fact check only verifies the sentences that were written.
38. **When the plan changes, keep the old steps as history, give each new step its own number, and name the legacy steps that it replaces and why**, in the plan and in every document that mentions the step. A replaced step is marked as replaced where it is listed, not deleted.
39. **A block of a runbook that needs a file or a value made by an earlier step first checks that it exists, and stops with a clear message**; it does not run on and produce a partial result (a bundle built before the upload of the laptop's result lacked that file and counted its own list).
40. **A setting is tested where the real system reads it, not as text:** a unit key in the wrong section is ignored by systemd, and a `grep` finds it in any section. Check section by section, and ask the real tool (`systemd-analyze verify`) on the real machine.
41. **A pattern or filter that judges real output is tried on real output before it is delivered:** a check for the word "unknown" would have failed a good boot because systemd also prints a warning about Ubuntu's own file.
42. **To stop a remote job, find its process numbers with a pattern that cannot match its own shell (the bracket trick) and kill by number; prove that it is gone by a measurement,** such as a file that no longer grows, not by a text search that can match itself. `pkill -f` kills the shell that runs it.
43. **A fix for a condition that can arise in two ways gets a test for each way, and a new test is shown to fail against the old code.** The first fix for a changed host key worked only after starting a stopped VM, and the real failure was a VM that was already running.
44. **An instruction block never contains a placeholder that the user must edit between two steps:** a value that comes out of one step is put into the next block by me once the output is pasted, or the step prints it and the next step reads it.
45. **A property that a rehearsal's stand-in cannot enforce, such as who may read a file, is tested by the first real run, and the rehearsal records at least which path was used:** a stand-in for `runuser` that does not enforce permissions hides every "the other user cannot read it" problem.
46. **A negative test is proved by breaking the code on purpose (a mutation) and seeing the test fail:** a test that passes on broken code tests nothing. A first attempt at a mutation can be a no-op, so check that it was applied.
47. **A search tool must not contain its own search text, and a failing check prints the reason itself:** build the pattern from two pieces and leave the kit's folder out; print the last lines of the log that explains the failure, so that one run is enough to diagnose it; and let a driver look at every node before it stops.
48. **A rehearsal tests the glue, not the third party's expectations:** Hadoop's checks (a reverse name for every DataNode, safe mode after a start) cannot be seen with stand-ins, so the first real multi-node run is the test, and every symptom is diagnosed from the nodes' own logs before any change.
49. **A test that gates a deletion runs with the privileges of the deletion, and a cleaning step verifies its result and aborts:** an unprivileged `[ -d ]` on a 0750 folder says "no such directory" and skips the deletion in silence; stop the daemons first, delete with `sudo`, and look afterwards.
50. **One odd number in a log is evidence to follow:** 7 blocks in a new cluster, and a block pool that names the builder's address and an old time, led to a defect that had been in every image since F0.3a's second image.
51. **A test hook that switches a rule off hides what that rule does to the real system:** the smoke test started with a hook that disabled the "settings count only from core-site.xml" rule, so it never met the failure in the ApplicationMaster. Run at least one test with the hook off, and prefer removing the rule (here, the settings) to testing around it.
52. **When a class is deleted, search for its name in every source tree, and compile what the sandbox cannot compile as early as possible:** the contract tests need Hadoop's test jars, so two stale imports cost a fleet round; the builder now compiles them right after the job.
53. **A test that fails in the same way on the control tests nothing about the thing under test, and a test setup must not contradict its purpose:** nine contract tests failed on plain HDFS too (a minimum block size) and so never exercised the wrapper; and the outsider test made its folder with the fleet's own wrapper, which an outsider cannot write into.
54. **A stand-in must behave like the real system in exactly the property that a test relies on, and the diagnosis must be proved by switching it off:** the flaky racing-writers test came from a file system whose exclusive create is not atomic; with the atomicity off it fails 4 of 4 runs, with it on 12 of 12 pass.
55. **A pasted block must stop at its first failure, and the build must not depend on a login:** an echoed STOP does not halt a paste, so use a guarded subshell that ends with a STEP-n-OK line; and build from files that are already on the machine and checked by fingerprint, not from a GitHub clone that needs `gh auth`.
56. **Switching off a layer also switches off what it did silently:** with cloud-init off nothing set each VM's host name, and Hadoop bound its ports to the VPC address. Before removing a layer, list what it does at boot (name, network, keys, hosts file) and test each item on a real VM.
57. **Run every cluster script against the real tools in the sandbox first, and never silence the error of a setup step:** `hdfs dfs -cp -r` does not exist (`Illegal option -r`), the error was hidden, and a failed setup looked like an attack that was not refused. Hadoop's own shell runs in the sandbox on a local folder.
58. **A stage that removes a capability must be the last stage that needs it:** the lock removed `sshd` and the next stage logged in. Test the sequence of stages, not only each script, and do the lock, the cleaning and the power-off in one session.
59. **Lint the commands that a driver generates, and print them whole:** a shell expansion put a stray word on a `gcloud` command and a truncated dry-run line hid it. Print every argument quoted, and check the grammar by machine.
60. **A pasted block prints its done marker only when its driver succeeded, and a variable that a block exports for a later stage is checked against every earlier stage that reads it:** use `if driver; then echo DONE; else echo FAILED; fi`; set a variable such as `REFERENCE` only for the stages after the file exists; and print the quota before a larger fleet.
61. **A conclusion from partial output is a hypothesis:** the first probe printed a few lines that looked like the answer while the parser hid the decisive events. Save the raw data, read the whole output, and state what is not yet known.
62. **A systemd unit is not a login shell:** its `PATH`, `HOME`, user and sandbox differ. Run the script once under the unit's own environment (`env -i` with the unit's variables) before the image is rebuilt, and test that every command resolves in the unit's `PATH`.
63. **Before a script filters or parses a third party's output, run the third party once and look at it:** the stand-in must use the real names (the exporter writes `.warc`, not `.warc.gz`), and a scenario with the real names must fail on the old code.
64. **Documents are committed when a step is finished end to end:** the code has run on the real cluster, the whole output has been read, and every sub-step is done. Interim findings stay in the chat and in the evidence folders; only a wrong statement or a piece that a teammate is blocked on is committed earlier.
65. **Test a guard against the version that must be refused and the version that must be accepted, with the exact text of the block, and do not assume that the sandbox's tools behave like the user's:** a fixed message with `grep -F` does not depend on the pattern mode.
66. **Reproduce a failure on the real kernel and the real userland before designing the fix** (QEMU with the image's own initramfs tools), and test each fix in both directions: the old logic fails, the new one passes.
67. **A stand-in for a system tool proves the script's logic, not the tool's behaviour:** the first boot of every new low-level layer is a step of its own, with the console watched.
68. **Test a watcher's patterns with the real console text of a good boot and of a bad one.**
69. **A tamper test uses a range that holds written data in any layout, and a control that shows that the tamper reached the disk.**
70. **A resource that a script creates proves its properties right after its creation** (for example the type of a disk), and the fake cloud of the rehearsal enforces the provider's rules.
71. **Capacity is part of the environment:** never retry a stockout in the same zone, use a fallback over the zones, and clean up each zone that failed.
72. **When a change touches a script, run again every rehearsal that runs that script,** not only the one that the change touched.
73. **Test a fix on the real files, on the machine that has them, before any rebuild:** the jar and the initramfs of two real builds exposed what synthetic files had not, and a rebuild costs much more than a read-only test.
74. **Do not name a cause that the evidence does not show:** say that it is unknown, and add a diagnostic that fires on exactly that failure.
75. **A mutant that another check catches proves nothing about the check under test:** plant the bug so that only the safety net can see it (a bug that undoes itself on the second pass, or that breaks the test's own plumbing, is caught by the wrong thing).
76. **A test needs a control that fails when the thing under test is wrong:** a check that cannot fail proves nothing (the first check of the verifier's consistency passed for a good and for a tampered reference alike).
77. **Read what a check requires before ordering it:** the repository's audit needs the working copy to be what GitHub has, so the order is push, audit, and the audit again on a fresh clone.
78. **Wait for readiness, not for status, and never hide the error of a step whose failure costs hours:** a VM that is RUNNING does not answer on SSH yet; show the error of the copy; fail at once when an input that saves hours is missing.
79. **A reproducibility test must include builds made on different days (or with a faked date):** a day-dependent datum cannot be seen when all builds are made on one day.
80. **Nothing is pushed before the exact commit has passed the whole run on the real cluster:** make a local commit, run everything on it, and push only with the commit id that the cluster printed.
81. **Every cloud stage that creates a VM falls back to other zones on a capacity error and is safe to run twice, and every failure prints the error lines of its log, not its tail.**
82. **Scan a script for the hazards of its shell before it is given, when it cannot be run here:** in PowerShell write `${name}:` and never `$name:` in a string.
83. **Read the last line of a test run, not a cut-off listing, and re-run a recorded number to the end before calling it wrong.**
84. **A rehearsal must not depend on the machine that runs it or on counts that grow:** fake every lookup of the host (its users, its files) and count from the files that are tested.
85. **Check a machine's state at the moment of use, not earlier:** a stage that cleans a machine removes what an earlier check saw.
86. **Every kit has its own state folder, and a pass needs its own inputs:** refuse to print PASS when the commit id is missing.
87. **Pass an input in the command, or name its file after what it holds:** never rely on a same-name upload replacing the old file.
88. **Run a rehearsal as an unprivileged user on a machine without the project's users before it is given:** root and a host user hide the ownership and user checks.
89. **A background helper must not inherit a lock:** close the lock's descriptor for the processes that outlive a stage (the ssh-agent of a copy).
90. **A name that is changed in one place must be changed in every place:** search for all its uses before a kit is given (the archive name was changed in the preparation stage and not in the build stage).
91. **Read the data before explaining a difference, and write an inference as an inference:** the expected cause of a 3-byte difference (a tool version) was wrong; the two lines were equal and the real cause was the archive name.
92. **Print a follow-up command from the same names that the kit uses:** a text copied from the earlier kit named the wrong push script.
93. **A preflight checks every quota that a later stage uses:** disks as well as CPUs.
94. **Look at where the earlier things of the same kind live before choosing a path:** the milestone kits are under `ops/kits/` and the first R4 kit was put directly in `ops/`.
95. **Run the whole list of gates against a changed input, not one gate:** the end to end kit was tested with one rehearsal and failed on another.
96. **Never hide a prompt behind a pipe, and test against the real command, not a stand-in:** a stop command that asks a question hung for 16 minutes.
97. **Replay a script's gates with the commands read from the script:** a retyped command hid that a new folder shows as one line.
98. **Select an uploaded file by its hash, not by its name:** Cloud Shell kept the old zip and saved the new upload under another name.
99. **A long block keeps printing:** a block that hid 60 minutes of kit output behind a file made Cloud Shell treat the session as idle and reset it.
100. **A cleanup respects the state of the run:** a disk copy that the sealing has finished is the sealed disk and must not be deleted.
101. **A gate is added to the real list only after it has run in the real environment:** passing in the sandbox is not enough.
102. **A fake can only enforce the rules its author knows:** validate every name locally against the provider's documented rules, and treat the first real run as the real test.
103. **Check the names and the rights before the first change, also in a dry run:** a setup that stops halfway leaves a partial state; a dry run that only prints commands cannot know the rules.
104. **Every scenario of a test starts clean:** a marker file that leaks from one scenario to the next can make a later scenario pass or fail for the wrong reason.
105. **Read the vendor's own code before a run that depends on its tool:** how a sign-in action hands its credentials to `gcloud` was in the code of Google's companion action, not in the documentation.
106. **Before pushing a tag that starts a workflow, check that Actions are on, and remove old uploads that share a name:** a tag pushed while Actions are off is not replayed, and a verifier that reads a zip by name reads a stale one.
107. **Read the whole line before you delete or change it by a pattern:** an automatic edit removed a second command that was on the same line, and a linter cannot see a missing command; read the result of every automatic edit and run the tests.
108. **A test must reach the check that it names:** assert which step stopped the run and not only that it stopped, and prove it by breaking that check (a mutant); a test that passes while its check is broken tests nothing.
109. **Describe a retry path only after replaying it:** a second attempt that is described in the instructions must be run against the state that exists after the first one.
110. **A test must assert a positive effect and not only the absence of an error:** a control passed because a variable still held an old value (mistake 223), and a test of a wait passed because its `cd` failed, so the program never ran (mistake 230); make each test fail on broken code, check that what it needs really ran (for example that both trees hold the kernel file), and prove it with a mutant (it extends rule 108).
111. **Compare two builds of one commit with no ignore list before you call a build reproducible:** an image compared with itself is identical by construction, and two commits mix the leftovers of the build with real changes; a list of ignored paths hides exactly what the comparison was meant to find, so remove what the build adds and keep `ignored=0` (mistake 224).
112. **A check that compares with a moment runs at that moment, and a resume proves its evidence:** the checks that compare a node's log with its final quote can only pass before the node adds more events; after a lost run, show from the first run's log that they passed, check that the failures of the repeat are exactly the expected ones, and run only the stages that remain (mistake 225).
113. **Look at the state before you retry:** a request that failed on the way back (a 502) may have done its work, and the retry then fails with "already exists"; ask whether the object exists, and whether it is the right one, before you make it again (mistake 226).
114. **Say which value you mean when you ask for one:** the commit id, the hash of a zip and the hash of a block are all "an id"; a command that needs one of them names it (mistake 227).
115. **Parse every script with the real interpreter, not with a look-alike:** a commit subject with an apostrophe inside a single-quoted PowerShell string failed only at the first real run; the real parser reproduced the error at once and now parses every laptop script before it is given (mistake 228).
116. **Give long text as a file and not as a pasted line:** a long message was cut in the middle and the shell waited for a closing quote; a file read with `git commit -F` cannot be cut (mistake 229).
117. **When a wait fails twice, read what you are waiting for before you wait longer:** two longer waits and faster disks were tried before the console of the VM showed emergency mode, which no wait can cure; print the console of a thing that does not answer, before it is deleted (mistake 231).
118. **Start a long run detached and make it restartable:** a run that is attached to a terminal or a session dies with it (twice); use `setsid nohup`, read the log with `tail`, skip finished stages, and check a resume (mistake 232).
119. **State a cause only as exactly as the evidence shows:** I wrote that the sealed disks carry the labels `UEFI` and `BOOT`; the probe showed only `UEFI` on them, and the console did not show which disk the label pointed at; separate what the evidence proves from what it implies, and say which is which (mistake 233).

## 5. Checklist for repeating the work

1. Create the master and worker as TDX Confidential VMs; check `dmesg | grep -i tdx` and `ls /sys/kernel/config/tsm/` on both.
2. Install `openjdk-11-jdk ant maven git libcld2-0 libcld2-dev` on both; add host aliases; ping both ways.
3. Download Hadoop 3.4.3, compare the SHA-512, unpack, set environment variables, write the four config files.
4. Format HDFS once, start the four daemons, run the Pi test, confirm 1 live DataNode and 1 running node.
5. Build `crawler-commons` and `language-detection-cld2`; record their commits; download the suffix list and record its hash.
6. Build the fork with `ant runtime`; record the job hash.
7. Put the seed file in a new HDFS folder; check the seed hash (57 bytes, prefix `14a80f8c8eaa`).
8. Run `ops/run-crawl.sh <seed-dir> <crawl-dir>` inside tmux, logging to a file.
9. Copy the WARC folders out of HDFS; hash them; count record types; list URLs; check `hostname:` lines.
10. Build a manifest per node, make a quote per node, check `MATCH`, hash the evidence files.
11. Copy evidence to Cloud Shell (VMs can be stopped); re-hash; compare by shell.
12. Verify the quote signatures on a machine with no Google credentials (`check -inform bin`, then with `-get_collateral=true -check_crl=true`); extract MRTD and RTMRs and count the distinct values per register.
13. Run the tamper tests on a copy of a manifest and on a copy of a quote; keep the logs and the tampered copies.
14. For a configuration change, rebuild: `conf/` is packed into the job file. Check the new job file's contents (a Python one-liner with `zipfile` is enough) and keep the old job hash.
15. Before touching the kernel: snapshot each boot disk, back up GRUB, pin the running kernel with a `grub.d` file and `grub-set-default`, and prove the pin with one reboot. Then install the packages (checksums verified) and request one boot with `grub-reboot`. Keep the reboot command in its own block.
16. After the boot: check the `measurements` folder, run the measurement script, request a quote with the log as input, and verify the signature off-cloud and the replay on two machines.
17. Run the crawl, then recompute every measured digest and compare. After any master outage, check the worker's daemons with `jps`.
18. Before a network change, back up `/etc/hosts` and the firewall rules. Apply a firewall with a self-undo timer that only a fresh login can cancel.
19. After a network change: check `yarn node -list` (the node name), HDFS safe mode and live DataNodes, and run the Pi example. Check the worker's task logs for okhttp right after a crawl, before any daemon restarts.
20. Prove the firewall with counted rules: probe the Hadoop ports over the ordinary address and the mesh address, in both directions, and read the drop counters before and after.
21. Unpack new code into a scratch folder on the master and test it there; commit only files whose fingerprints equal those recorded when they ran, and check them from a fresh clone.
22. Build the job in a scratch clone, never in the measured tree, and compare it with the measured job entry by entry (`job_compare.py`) before any crawl comparison.
23. Before a crawl: on the worker rotate the logs and restart the NodeManager; run `wrapper-jar.sh verify <job file>` (it must say `CLASSES-SAME`); right after the crawl pack the container logs.
24. In wrapped mode use `ops/run-crawl.sh` (no wrapper options); for the unwrapped control switch both nodes with `cluster-mode.sh plain --restart-yarn` and switch back afterwards.
25. Run the NameNode comparison over a window that starts at the rotation (so that the seed upload is in it), read its `known` lines, and run it once with `--strict` and once with one wrapper log removed.
26. A wrapped crawl: rotate the logs on both nodes, put the seeds in, list HDFS before, crawl in tmux, list HDFS after, check the worker's task logs before any restart, collect both nodes' logs, run `audit_compare.py` with `--require-hosts` for both nodes.
27. When two crawls differ, look at the earlier runs (a control) and at the page itself (a deployment identifier, new links) before explaining the difference.
28. Test any new checking tool with planted faults, and keep timestamps out of compared text.
29. For everything after the pilot (Milestones 2 to 5) follow the milestone reports: each step has its kits in `ops/kits/` and its runbook. Before any commit run `ops/attested/preflight.sh` (rule 36).

## 6. Security hygiene

- Keep GitHub tokens, passwords and API keys off the VMs. Commit from the laptop and `git pull` on the VMs.
- Do not open Hadoop ports to the internet; add no firewall rules.
- Do not put personal data or secrets in `nutch-site.xml`: its values are written into WARC files and committed.
- Remove stray SSH keys created on a VM by a mistaken command.
- Treat unknown folders under `/sys/kernel/config/tsm/report/` as someone else's.
- The repository is public: commit scripts only, and keep quotes, boot logs, manifests and WARC files out of it.
- Do not install extra packages on a VM you plan to measure; use the tools already there (Python's `zipfile` instead of `unzip`).
- WireGuard private keys stay on the node that made them (root only, mode 600). Never print, copy or commit them; only public keys travel.
- The wrapper's logs and the HDFS listings are plain local files. They are an engineering proof for the author, not evidence against someone with root. `audit.sh rotate` moves logs aside; it deletes nothing.
- Do not build in the measured tree: a build overwrites the job that the measurements and earlier runs refer to.
